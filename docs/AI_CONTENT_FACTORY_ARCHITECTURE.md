# AI Content Factory architecture

The Admin route `/admin/ai-content-factory` uses the existing Admin shell and service-role API (`/api/admin/ai-content-factory`). Only authenticated admins can call it. Students continue to read published `ielts_exams` and pinned `ielts_exam_versions`; their requests never invoke synthesis.

The factory uses `ai_factory_jobs` as a persistent queue. A separate Python process atomically claims a Listening audio job, renders dialogue turns with Kokoro, stores the MP3 in private `ai-factory-drafts` storage, and writes segment timing, technical QA, evidence intervals, and usage records. Admin listens to a ten-minute signed URL and explicitly approves the audio. Approval copies it to `ielts-audio`, creates a new exam revision, and leaves the exam in `needs_review`. Existing bank actions mark it ready and publish it. `reviewExam` requires an approved job matching the current version for every factory skill.

`src/lib/ai-factory/text-generation.ts` prepares original Academic practice drafts for Listening Part 1, Reading, Writing Task 2 and Speaking Part 2/3 through a separate Gemini key. `draft-validation.ts` checks their schema, task structure, answer alignment and Reading evidence. Failed QA never imports an exam. Passing text drafts enter `awaiting_review`; generated Listening scripts enter the audio queue. Admin must inspect and approve each draft, then separately mark the exam ready and publish. These are short practice tasks, not full IELTS mocks. Model token counts are recorded with each job; they are not a billing statement.

`.github/workflows/ai-factory-text.yml` schedules four slots between 01:37 and 02:07 Asia/Ho_Chi_Minh: Listening, Reading, Writing and Speaking. It produces at most one draft for each skill per UTC day, with the database daily limit set to five total jobs. It makes no model request unless a separate key, `AI_FACTORY_FREE_TIER_CONFIRMED=true`, `AI_FACTORY_FREE_TIER_ONLY=true` and `ai_factory_settings.generation_enabled=true` are all present. The workflow runs on a standard public GitHub runner. The Admin manual generation route needs the same three environment values in Vercel. Never use the student-facing Gemini key for this factory.

The original Part 3 pilot is in `src/lib/ai-factory/pilot.ts`. It contains 20 dialogue turns, three fixed voices and ten scored questions. Worker cache keys include the model hash, voice, pace and canonical text. Generated audio is reused across students.

The factory's database migration is `supabase/migrations/202610270010_ai_content_factory.sql`. It adds settings, voice profiles, jobs, segments, QA and usage, with admin-only read policies. Mutations are made by the server's service-role client or by the private worker. No student-facing generation endpoint exists.
