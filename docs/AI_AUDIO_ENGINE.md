# Gemini-first audio engine

`services/audio-worker/worker.py` runs without an inbound HTTP listener. It polls `ai_factory_claim_job` and uses Gemini 3.8 Flash TTS first, with one request per transcript turn so answer evidence keeps exact time offsets. The four stable script voice IDs map to Gemini voices: `bf_emma` → Kore, `bm_george` → Charon, `af_heart` → Aoede, `am_michael` → Puck. Accent is requested in style metadata; admin listening QA must verify it. Gemini calls require `AI_FACTORY_GEMINI_API_KEY`, `AI_FACTORY_FREE_TIER_ONLY=true`, and `AI_FACTORY_FREE_TIER_CONFIRMED=true`. The audio workflow uses the same confirmed free-tier key as text generation. The key must belong to an unbilled project; the worker does not verify billing state itself. See [Google's TTS API](https://ai.google.dev/gemini-api/docs/speech-generation) and [current pricing](https://ai.google.dev/gemini-api/docs/pricing).

If the key is missing or Gemini fails, including HTTP 429 quota errors, the worker renders the **entire** draft with Kokoro. It records the actual provider, model, fallback reason, and `needs_regeneration=true` in `ai_factory_qa.technical.generation`; Admin Audio Studio and QA display the marker. When quota returns, Admin can use **Xếp hàng tạo lại bằng Gemini** to create a separate draft from the same script and exam version. The original Kokoro draft remains available for comparison. The action is limited to the current unpublished exam version and does not replace student-visible audio automatically; the new draft needs QA and human review. Kokoro weights are checked against SHA-256 `496dba118d1a58f5f3db2efc88dbdc216e0483fc89fe6e47ee1f2c53f18ad1e4` before inference. The weight file and Kokoro 0.9.4 are from [hexgrad/Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M) and [hexgrad/kokoro](https://github.com/hexgrad/kokoro), both Apache-2.0; verify voice and dependency terms again before deployment.

Technical checks include mono 24 kHz output, finite samples, amplitude, clipping, long silence, segment count, final MP3 decoding, storage size and evidence turn intervals. Faster Whisper `base.en` performs a local ASR pass and records the recognized transcript, word error rate and answer phrases it did not recognize. ASR disagreement triggers manual review; it is not proof of a TTS error. An admin must still listen and inspect every answer.

## Listening practice test pacing

Each Part MP3 now starts with an original practice-test cue naming the Part, the scene and its question range. A 30-second question-preview pause and a spoken start cue follow before the dialogue. After the dialogue, a spoken closing cue gives 20 seconds to check answers for Parts 1–3; Part 4 of a full test gives two minutes. These intentional pauses are recorded with start/end times in `ai_factory_qa.technical.sections[part].timeline`; the dialogue answer offsets in `ai_factory_segments` include the intro and preview. Unplanned silence over three seconds still fails technical QA.

For a four-Part job, the sum of the actual rendered MP3 durations must be 25–35 minutes before the job can enter `awaiting_review`. This is a tolerance around the approximately 30-minute IELTS Listening format, not a promise of an exact 30-minute file. Short standalone Part practice is exempt from that full-test duration gate. The four Parts remain separate MP3 files in the bank. In the full-test player, finishing one Part advances to the next and attempts to play it; browsers that block the next playback require a tap on Play. This is original IELTS-style practice audio, not official IELTS audio. References: [IELTS Listening format](https://ielts.org/take-a-test/test-types/ielts-academic-test/ielts-academic-format-listening), [IELTS advice on question preview time](https://ielts.org/news-and-insights/helping-students-improve-on-the-ielts-listening-test-develop-listening-skills-for-the-ielts), and [British Council computer-test answer check time](https://takeielts.britishcouncil.org/sites/default/files/listening_part_3_matching_questions.pdf).

Local dry run after activating a Python 3.11 environment and installing `requirements.txt`:

```powershell
node scripts/export-ai-factory-pilot.mjs "$env:TEMP\ai-factory-pilot.json"
python services/audio-worker/worker.py --local-pilot "$env:TEMP\ai-factory-pilot.json" services/audio-worker/output
```

The resulting `pilot-part3.mp3`, `ai_factory_segments.json` and `ai_factory_qa.json` stay local. A local run is useful for technical verification but does not create an approved or student-visible exam.
