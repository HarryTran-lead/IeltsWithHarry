# Implementation and operational contract

- Code: `src/lib/news/question-factory-v2/{types,validate,prompts,provider,index}.ts`; tests and machine-readable corpus: `tests/fixtures/news-factory-v2.ts`, `tests/news-factory-v2.test.ts`.
- On Vercel production, the scheduler and authenticated admin preview use V2 by default. Preview and local environments retain the legacy generator. `NEWS_QUESTION_FACTORY_V2_PUBLISH_ENABLED=false` is an explicit emergency off switch; `true` enables V2 elsewhere. The authenticated preview can request `factoryVersion:"legacy"` to compare the old generator or `factoryVersion:"v2"` to force V2.
- A V2 attempt reserves a 365-day DB hold immediately after the existing claim, before sending requests. The existing publish RPC receives only the original fields. This is intentionally conservative: quota, quality or uncertain network failures need a human to inspect the article fingerprint before resetting retry. No schema migration or data rewrite occurs.
- Generation request: title, full article, selected form distribution, passage intelligence, candidate questions and source quotes with exact offsets. The legacy excerpt is used only to decide target count and viable types. The second request receives the full article and only IDs, types, group IDs, prompts and choices. The QA response must independently solve each item and mark paraphrase faithfulness, distractor fairness and form validity; it is compared to the author's key after the request. There is no automated correction or third request.
- The process cache stores only successful results, keyed by SHA-256 of factory version, model, article ID, title, full article and editor guidance. It is an optimization within one worker, not durable budget accounting.
- The response audit reports the actual number of attempted calls and provider-reported token usage; missing usage remains null. It records candidate, structural and QA counts and reasons for a hold.
- Operational caveat: the 365-day hold uses the existing `retry_after` field and does not encode an immutable per-article request ledger. Admin preview is an explicit separate invocation and is not counted against the scheduler's DB hold. A durable global budget ledger and evidence-column ACL would require a migration, which this task forbids.
