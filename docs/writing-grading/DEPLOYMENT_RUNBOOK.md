# Deployment and rollback

1. Keep `WRITING_AUTOGRADING_ENABLED=false`. Back up the **development** Supabase database; verify project ref `bhactqaxcvusmpeooxwi` before applying `202611100004_writing_grading_foundation.sql`. Do not reset/seed databases.
2. Run unit, RLS/integration and authenticated UI checks on development. Verify existing Writing submit and old feedback still work. The feature flag should display an unavailable message while retaining the essay.
3. Provision a private worker host. Store `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `WRITING_LOCAL_MODEL_URL=http://127.0.0.1:11434`, `WRITING_LOCAL_MODEL_ID`, and exact `WRITING_LOCAL_MODEL_REVISION` in the host secret store. Never expose Ollama externally or place service role credentials in client code. Install an approved local model artifact out of band; disable public download on the runtime host. A privileged review must insert an `approved` `writing_model_registry` row for each task type with artifact hash, rights decision and evaluation report reference; the worker refuses models absent from this registry. Run `npx tsx scripts/writing-grading-worker.ts --once` for a smoke claim, then supervise the continuous command without `--once`.
4. Perform real Task 1 and Task 2 inference on licensed synthetic essays, teacher review, fact-grounding and latency/VRAM measurements, security/RLS tests and backup recovery. For an independently labeled, deidentified Gold JSON array, run `npx tsx scripts/evaluate-writing.ts gold.json`; the report always includes sample counts by task. No such live measurement has been completed in this branch. The developer laptop reports GTX 1650 Ti Max-Q, 4 GB VRAM; this is not an inference-capacity result.
5. After passing review, set `WRITING_AUTOGRADING_ENABLED=true` only in the isolated development Preview and test authenticated submit → queue → result. For production, repeat migration/backups on ref `vpkhriywprepuhrbarye` first, then deploy the validated worker and app with the server-only flag. Start with a limited cohort only after a cohort gate is implemented.

Emergency rollback: set `WRITING_AUTOGRADING_ENABLED=false` to stop new jobs; keep the worker paused if model output is suspect. The app still serves existing submissions and stored results. Do not drop the new tables or rewrite old `ielts_attempts`; investigate/review bad results and deploy a new pipeline version before regrading.
