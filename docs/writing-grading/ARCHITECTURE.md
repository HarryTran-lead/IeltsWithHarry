# Writing grading architecture

The existing bank submit route persists a Writing attempt first. When `WRITING_AUTOGRADING_ENABLED=true`, it creates one `writing_grading_jobs` row for the submitted attempt and pipeline version. The new `POST /api/ielts/bank/writing-grading` also enqueues an older Academic attempt, or retries a failed job. A unique constraint prevents duplicate initial jobs. The endpoint never accepts a client-supplied user ID or score. The app admits at most 20 grading jobs per account per Vietnam calendar month and 30 jobs globally in a rolling 24-hour window. These are admission limits, not a promise of Cloudflare capacity; stronger atomic quota enforcement remains a hardening item.

The private worker (`scripts/writing-grading-worker.ts`) uses a service-role-only `writing_claim_grading_job` Postgres function with `FOR UPDATE SKIP LOCKED` and a 180-second lease. Up to three attempts are allowed. Before inference it requires an `approved` row for the exact model revision and task type in `writing_model_registry`. It calls only a co-located Ollama HTTP endpoint on loopback. `writing_finish_grading_job` fences stale workers and commits the result/job transition atomically. A unique `job_id` result prevents duplicate visible grades. Errors retain the original submission and lead to retry or failure; there is never a fallback band.

Task 1 requires admin-verified source facts tied to the exact exam version. Missing facts lead to `needs_review` without inference. Task 2 sends the original prompt and essay to the local model. Both require four separate criteria, exact UTF-16 essay quotes/offsets, bilingual reasons and validated error spans. Data-accuracy claims require verified fact IDs. Invalid JSON or unsupported evidence is rejected. This is a validation boundary, not proof that the model is accurate.

`GET /api/ielts/bank/writing-grading?attemptId=...` checks ownership and returns a private status/result. The result page polls queued/analyzing jobs; the old Gemini feedback route is read-only for existing records. `GET/POST /api/ielts/bank/writing-source-facts` and `GET/POST /api/ielts/bank/writing-review` require an existing admin account. The existing bank admin page has a Writing QA tab for source facts and human criterion labels. No public inference endpoint is added.

The model adapter is intentionally unconfigured. A pinned local model, an independent human-rated evaluation and a private worker host are required before enabling jobs. The current UI shows a truthful unavailable state while the feature flag is off.

`scripts/evaluate-writing.ts` accepts only deidentified `(sample_id, task_type, human_band, predicted_band)` records and reports task-specific counts, exact/within-band rates, MAE, RMSE and quadratic weighted kappa. It does not train or silently export learner essays. Registry/dataset manifest rows default to blocked/quarantined, and no approved rows are seeded.
